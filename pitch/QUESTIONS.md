# Judges' questions and honest answers

Written 2026-11-14 by reading the code. Each answer is what a person can say out loud. The line under it is where to look. If a line number has moved, search the file for the quoted words. Where something is built but not run or not connected, the answer says so.

## 1. What is real and what is made up?
The code is real and runs: the rules engine, the game view, the hidden-score reveal, the announcer, the soccer game. The player names are real NFL players and real footballers. The game you watch is made up: it was built from invented stat lines, so no play really happened. The two managers, the league and its standings are invented sample data.
Proof: `pitch/REAL-AND-SIMULATED.md`; `data/statlines/week11.json` line 2 (`"invented": true`); `data/league.json` (`"invented": true`).

## 2. What does Jev decide, and what does the rules engine decide?
Jev is a decision model from TypeSafe AI. At a snap it is given the situation and a list of legal calls, and it returns a probability for each. It writes no text. The game maker then draws a call using those probabilities. The rules engine decides everything else: yards, downs, turnovers, touchdowns, scoring and whether a game is legal.
Proof: `engine/jev.js` lines 1 to 3; `engine/make-game.js` line 238 (`choose`); `js/rules.js` line 104 (`apply`).

## 3. How many plays did Jev choose in the game the app plays?
40 of 84. The other 44 were chosen without Jev, either because only one legal option was left or by an even draw. The game file records which plays Jev chose, with the probabilities.
Proof: `data/games/week11-football.json` lines 950 to 960 (`report`: `plays` 84, `playsChosenByJev` 40, `model` jev-1.14.0).

## 4. Is the game a real NFL game?
No. The game maker was started with `--from-sample`, so the targets are the stat lines of our invented sample game, and it built a new legal game that reproduces them. The final, 17 to 14, is a made-up result.
Proof: `engine/make-game.js` line 364 (`--from-sample`); `data/games/week11-football.json` line 950 onward.

## 5. How do you know the game is legal and the numbers add up?
Every play goes through the rules engine, and the finished game is replayed from scratch and compared with the target stat lines. A game that does not match is thrown away. The report says it matched.
Proof: `engine/make-game.js` lines 12 and 13; `data/games/week11-football.json` (`matchesTargets: true`); `node tools/validate.js` for the sample game.

## 6. Why are the scores hidden?
That is the product idea: if you already know your score, there is nothing left to watch. When a viewer chooses "opt in", points, stat lines, leaders and floating points are masked until the final whistle. In this demo the wait is only until the replay ends, not a week, and the choice is stored in the browser.
Proof: `js/app.js` line 46 (`fr.optin`, mask text), lines 83 to 86 (`masked`, `setFloaters`), line 418 (the opt-in card).

## 7. Do two managers really opt in?
No. There is one viewer, no accounts and no second manager. The choice is saved in that browser's local storage. The service can record opt-ins in a table, but nothing in the app calls it.
Proof: `js/app.js` line 45; `server/index.js` (route `/games/:id/optin`); no call to the service anywhere in `js/` (the only `fetch` is `js/app.js` line 144, for `data/scoring.json`).

## 8. What does the database store, and does the app read it today?
Every play is a row with the time it happened in the game, its fantasy points and Jev's why. Two continuous aggregates give points per player per game and per team per quarter. The schema was run on a real Tiger Data database, and a small service saved and returned plays there. The app does not read the database today: it plays from a game file.
Proof: `db/schema.sql` lines 6, 16, 23, 40 (hypertable), 46 and 62 (aggregates); board answer from the boss on D3 in `board/BOSS.md`; `server/test.js` for the routes against a fake database.

## 9. What was not tried on the database?
The seed file, the opt-in and health routes, pushing a whole game, and the optional certificate check were only tested against a fake database. The summary read came back empty on the first real run because the aggregates had not refreshed yet.
Proof: `db/seed.sql` (generated by `db/make-seed.js`); `server/README.md` section "Not checked"; `board/BOSS.md` answer on D3.

## 10. What is Scout, and has it run for real?
Scout is a research agent built with LangChain's deepagents. It plans, calls tools that read a public stats source, works out player tendencies from 0 to 1, and writes profiles with the source and date next to every number, plus a log of every step. The agent has not run for real: we had no model key. Its tools did run live against Sleeper's public API, and a plain script (`fill_profiles.py`, no model) used them to fill every player's tendencies from real 2026 numbers. Its wiring into deepagents passed offline checks only.
Proof: `agents/scout/README.md` "Status"; `agents/scout/fill_profiles.py`; the log in `agents/scout/runs/`; `data/profiles/GOB.json`.

## 11. Do the player profiles shape the game you watch?
Not yet. The profiles hold real numbers now, and the game maker and the announcer can read them. But the game the app plays was built before they were filled, when Jev was told "not available" for tendencies. No game has been rebuilt with them.
Proof: `engine/make-game.js` line 337 onward (`player_tendencies`); `js/announcer/index.js` lines 17 to 20; `data/profiles/PYT.json`; `data/games/week11-football.json` (`report`).

## 12. How does the announcer make its lines?
From templates, not from a model. Each kind of play has several variants in two styles. The announcer fills in names, yards and the spot from the rules engine's result and avoids repeats. The browser's speech voice says the line. ElevenLabs voice ids are chosen, but recorded audio was not in the repository when this was written.
Proof: `js/announcer/lines.js` lines 1 to 14; `js/announcer/index.js` lines 1 to 25; `js/announcer/voices.js` line 1; `js/announcer/check.js` (script check).

## 13. What does soccer share with football?
The same pattern: a game is a list of events, a rules file works out goals and score, every result carries fantasy points, and the app, the announcer and the speed control work for both. Soccer has its own pitch, plays, players and scoring. It is shown in the app inside a frame when you switch sport. Its match is scripted, not built by the game maker or Jev.
Proof: `docs/CONTRACT.md` section 6 (line 55); `js/sport.js` lines 13 to 15; `soccer/js/fantasy.js`; `node soccer/check.js`.

## Claims to avoid on stage

- "Real game", "real results", "real scores" or "real stats". The game and every stat line are invented.
- "Two managers" or "a week of waiting". It is one viewer and the choice sits in the browser.
- "Powered by AI" for the whole game. Jev chose 40 of 84 plays and writes no text. The announcer lines are templates. Scout has not run.
- "The game uses real player tendencies". The profiles have them, the game was built without them. "Scout, our AI agent, researched the players". A script did; the agent has not run.
- "Saved in the database" or "live from the database". The app does not read or write it.
- "Tested on phones". Tests ran in a headless browser at phone width only.
- "The announcer speaks with ElevenLabs". Not in the repository when this was written.
- Any number you did not read from a file in the last hour. If unsure, say "I would have to check".
